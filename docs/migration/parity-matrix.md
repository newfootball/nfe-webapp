## Routes, HTTP and redirects

O: the JSON enumerates 33 source entry points. Successful page rendering is expected to return 200, but actual wire statuses, including streamed responses, are **R** until measured. `notFound()` is invoked for missing user/post, non-owner edit and invalid SEO parameters; verify the actual 404 status and body over HTTP, including streaming. No status is asserted solely from the UI. Authenticated access and redirects must be checked on direct requests and client navigation: the [private layout](../../app/%28home%29/%28private%29/layout.tsx) redirects unauthenticated users to `/sign-in` on the client; the [admin layout](../../app/%28home%29/%28private%29/admin/layout.tsx) checks the session and role on the server and redirects non-admins to `/`. The [auth layout](../../app/%28home%29/%28auth%29/layout.tsx) redirects signed-in users to `/` on the client. Server guards also exist on individual pages; do not assume the client layout alone prevents data access. Capture exact redirect HTTP statuses and Location headers for server and client cases rather than assuming 302 or 307 (#51, #60, #65).

O: `/` redirects to `/splash` when `seen_splash` is absent/false ([home](../../app/%28home%29/%28public%29/page.tsx), [cookie action](../../src/actions/cookies.actions.ts)); onboarding redirects absent session to `/sign-in` and completed onboarding to `/`; edit-profile redirects a missing user to `/profile`; post edit rejects absent/non-owned posts via `notFound()`. R: exercise each branch, reload and navigation; verify no loops (#51, #53, #56, #61).

O: [reset-password API](../../app/api/auth/reset-password/route.ts) implements POST: invalid email 400, known and unknown valid email 200 with same message, exception 500; malformed JSON enters the exception path. [catch-all auth handler](../../app/api/auth/[...all]/route.ts) delegates GET/POST to better-auth. R: record actual methods, responses, cookies, OAuth callback and recovery token behavior, including expired/invalid token and email delivery (#51, #52). Server actions are separate mutation surfaces, not additional `route.ts` endpoints: test direct calls and authorization as well as UI.

O: [sitemap](../../app/sitemap.ts), [manifest](../../app/manifest.ts), [app metadata](../../app/layout.tsx) and [PWA config](../../next.config.ts) provide metadata endpoints/assets outside the page/route inventory. R: capture `/sitemap.xml`, `/manifest.webmanifest`, icons, service worker and offline response/status, cache update and upgrade of an already installed PWA; check public historical URLs, canonical/OG metadata, SSR HTML, invalid params and permanent redirect targets/loops where a URL changes. Verify ID versus slug routes from real inbound links rather than assuming slug support (#61, #62, #65). Position/city allowlists and generated sitemap URLs are source-defined in their respective pages and sitemap.
